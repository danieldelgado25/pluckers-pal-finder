MyStaticEstimation.txt - our improved static estimation functions
=================================================================

Code: improved_estimation_opening() and improved_estimation_midgame_endgame()
in morris_core.py. Used by MiniMaxOpeningImproved.py, MiniMaxGameImproved.py
and TournamentAgent.py. Like the handout's functions, both score a board from
White's point of view (positive = good for White).


1. Features
-----------

  pieces      number of pieces on the board (W minus B).
  mills       complete mills a side owns: three of its pieces on one line.
  potential   "open twos": lines with two of a side's pieces and an empty
              third point. Each one is a threat to close a mill.
  junctions   pieces on the seven points where four lines meet
              (b1 f1 b3 f3 b5 d5 f5). Opening only.
  mobility    sliding mobility: number of (piece, adjacent empty point)
              pairs. A side with exactly 3 pieces hops anywhere, so it gets a
              fixed mobility of 8 instead.
  blocked     pieces with no empty neighbor.


2. Why these features
---------------------

* Pieces decide the game: you win by taking the opponent down to two pieces.
  Every other feature exists to predict future changes in this count, so it
  gets by far the largest weight.

* Mills and potential mills are how pieces are captured. The handout's
  opening function only counts pieces, so before the first capture every
  placement scores 0 and MINIMAX takes the first empty point in index order
  (a0). Potential mills reward placements that create threats and punish
  leaving the opponent's threats open. A complete mill matters after the
  opening because it can be "opened" and closed again to capture repeatedly.

* Junctions have four neighbors instead of three, so pieces there take part
  in more lines and are harder to block. This matters most in the opening,
  when the shape for the rest of the game is set.

* Mobility and blocked pieces: a side that cannot move loses. The handout's
  midgame function only counts Black's moves (including every capture
  variant). We count both sides' mobility, add a bonus for each blocked
  opponent piece, and treat a side with no slide as lost unless it can hop.


3. How they are combined
------------------------

A weighted sum. The weights are ordered so a more important feature can never
be outweighed by a plausible amount of a less important one: one piece
outweighs several potential mills, and one potential mill outweighs a few
mobility points.

Opening:
    100 * (piecesW    - piecesB)
  +  25 * (potentialW - potentialB)
  +  10 * (millsW     - millsB)
  +   4 * (junctionsW - junctionsB)
  +   2 * (mobilityW  - mobilityB)

Midgame/endgame:
    if piecesB <= 2 or Black cannot move:  +10000
    if piecesW <= 2 or White cannot move:  -10000
    otherwise
      1000 * (piecesW    - piecesB)
    +   60 * (millsW     - millsB)
    +   40 * (potentialW - potentialB)
    +    8 * (mobilityW  - mobilityB)
    +   12 * (blockedB   - blockedW)

The midgame keeps the handout's 1000-per-piece scale and its +-10000 win/loss
values, so the two functions are easy to compare.


4. Why we believe it is better
------------------------------

* It sees threats (potential mills) before a capture happens. The handout's
  functions only notice a capture once it is inside the search depth.
* It evaluates both sides symmetrically. The handout's midgame function
  ignores White's own mobility and blocked pieces.
* It scores mobility by counting piece/empty-neighbor pairs and does not
  generate every Black move (with every capture variant) at each leaf.
  It is still about 1.8x slower per call than the handout's function, because
  it checks all 18 lines several times. That cost is worth it, because it
  judges positions much better.
* Practice games with play.py (ALPHA-BETA, depth 3, same search for both
  sides): improved beat the handout estimation playing White and also playing
  Black. The tournament agent beat the handout's depth-3 player with both
  colors as well.


5. Positions where the improved function chooses a different move
-----------------------------------------------------------------

Reproduce with depth 2, for example:
    python MiniMaxOpening.py board1.txt out.txt 2
    python MiniMaxOpeningImproved.py board1.txt out.txt 2

Example 1 (opening): xxxWxBxxxBxxxxxxxWxxxxx    White on b1 b5, Black on f1 b3

    6 .-----------.-----------.
      |\          |          /|
    5 | W---------.---------. |
      | |\        |        /| |
    4 | | .-------.-------. | |
      | | |               | | |
    3 .-B-.               .-.-.
      | | |               | | |
    2 | | .---------------. | |
      | |/                 \| |
    1 | W---------.---------B |
      |/          |          \|
    0 .-----------.-----------.
      a b c       d       e f g

  Original: place a0  -> WxxWxBxxxBxxxxxxxWxxxxx   (MINIMAX estimate 0)
  Improved: place f5  -> xxxWxBxxxBxxxxxxxWxWxxx

  No capture is possible within two plies, so every move scores 0 with the
  handout's function and it takes the first empty point, a0. a0 only joins
  b1 on the diagonal a0-b1-c2. The improved function plays f5, a junction,
  which makes the open two b5-.-f5 and forces Black to spend its next
  placement blocking d5.

Example 2 (midgame): xWWWWxxxxBxBWxBBBWxBWxx
    White: d0 g0 b1 d1 f3 b5 a6   Black: b3 e3 c4 d4 e4 f5

    6 W-----------.-----------.
      |\          |          /|
    5 | W---------.---------B |
      | |\        |        /| |
    4 | | B-------B-------B | |
      | | |               | | |
    3 .-B-.               B-W-.
      | | |               | | |
    2 | | .---------------. | |
      | |/                 \| |
    1 | W---------W---------. |
      |/          |          \|
    0 .-----------W-----------W
      a b c       d       e f g

  Both functions close the mill b1-d1-f1, but with different pieces.
  Original: g0 -> f1, remove b3   -> xWxWWWxxxxxBWxBBBWxBWxx
  Improved: f3 -> f1, remove e3   -> xWWWWWxxxBxxxxBBBWxBWxx

  The original moves the g0 piece, which breaks up the open two d0-g0. The
  improved move keeps d0 and g0 in place, so White threatens b1 -> a0 to close
  a0-d0-g0. No black piece is next to a0, so Black cannot block it and White
  gets a second capture next turn. The original function only counts Black's
  moves, so it cannot see this threat.
